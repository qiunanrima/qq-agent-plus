# 小米运动健康插件

适配 QQ Agent Plus apiVersion 2 的独立插件，默认不安装、不启用。
参考 [ahwhshen/xiaomi-health-plugin](https://github.com/ahwhshen/xiaomi-health-plugin)
的中国区登录和查询实现；加密原语经 MIT 授权移植（见 LICENSE），其他宿主适配独立实现。
二维码生成器来自仓库已有的 Kazuhiko Arase MIT 实现（qrcode.js 保留版权声明）。

## 安装和使用

1. 在源码根目录打包：
   `node scripts/plugin-pack.mjs examples/plugins/xiaomi-health --out dist/plugins --json`
2. 控制台 → 插件 → 手动安装，上传 `dist/plugins/xiaomi-health-1.0.7.tar.gz`。
3. 启用插件，打开插件详情，勾选「已了解并启用非官方接口」，保存。
4. 点击「扫码登录」，用已登录的小米运动健康 App 扫码并在手机上确认。
5. 点击「检测登录」检查健康查询接口。
6. 开启「允许 Agent 读取健康数据」并保存，才能在管理员私聊查询。升级旧版也默认禁止读取，
   不因已有登录而自动授权。Agent 自行读取前，插件直接发出固定的私聊提示（指标和天数，不含数值）；
   提示发送失败则不读取、不自动重试。关闭开关立即拒绝后续 Agent 查询；登录凭据保留。
   控制台扫码与检测登录不受这个开关影响。
   管理员当前私聊明确提出的查询，在对应指标和天数范围内不另发提示；由配套宿主从触发消息判断，
   不接受模型参数声称已授权。含义不明确或超出请求范围时仍提示，旧宿主无法识别时也仍提示。

需要宿主支持手动重定向与中间响应 Cookie（本次改动），仅看版本号不能保证旧版可用。
群聊及非管理员私聊均拒绝，模型提供的 channel 参数不能绕过权限检查。
控制台登录管理不向模型返回二维码 URL、Cookie 或账号标识。

## 范围

- 中国区、本人的一个小米账号。
- `xiaomi-health__query`：metric 为 steps / sleep / heart_rate / all，days 为 1–7。
- 步数、距离、热量与目标；睡眠总时长/评分/分期时长；心率日统计与最近采样。
- 按 Asia/Shanghai 的自然日查询；睡眠时长单位为分钟，记录时间戳为 Unix 秒。
- 没有记录与缺失字段分别返回空数组与 null，不补成 0，不当成实时数据。
- 不自动同步、不自动播报、不写入长期记忆，不操作外部健康记录。
- 禁用后停止插件进程，凭据保留。重新启用可继续查询。
- 移除账号：取消正在进行的扫码，在插件设置清除「加密登录会话」。
  控制台 API 也可调用 login 工具的 logout 动作；这只移除本地凭据，不撤销小米端登录。
- 卸载保留宿主凭据和插件数据；需要彻底移除时先清除会话，再卸载。

## 登录与网络边界

使用小米 App 的非公开消费者接口 `hlth.io.mi.com`，不是官方开放平台 OAuth；
扫码建立的账号会话不具备官方细粒度授权保证，接口可能随时变化，也可能不符合平台服务条款。
2026-11-04 已在本地临时控制台完成本人扫码、加密保存及真实步数/睡眠/心率查询验证；
其他账号和设备兼容性仍需验证。服务器必须同步配套宿主改动并重启，不能只升级插件包。

1.0.3 补齐 STS 重定向参数中的 serviceToken 和扫码/STS Cookie 中的 cUserId；
凭据缺失时只报告缺失字段名称，不输出票据、不覆盖已有会话。

全部网络经宿主 cap.http.request；插件不直接 fetch、不开放监听端口。
仅允许 HTTPS 小米账号域 account.xiaomi.com 及其子域（扫码服务动态分配登录/轮询子域），
以及精确主机 sts-hlth.io.mi.com、hlth.io.mi.com。
登录按跳读取响应 Cookie；每跳重新经过宿主 SSRF/DNS/域名守卫。
Cookie 按精确主机分开保存，passToken 只发往小米账号服务。
持久化仅使用宿主 cap.secrets.set，加密保存为 session 字段，不使用普通 storage 或日志。
HTTP 401 时只尝试刷新一次；刷新失败要求重新扫码，其他错误不自动重试。

## 回滚

停用或卸载此插件即可停止全部功能，无健康数据库需要迁移。
本插件未发布到远端索引，使用上述本地包安装。
