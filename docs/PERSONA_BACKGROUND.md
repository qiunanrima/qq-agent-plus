# 角色背景知识

在「设置 → 人设 → 角色背景知识 · Markdown」导入或编辑一份 `.md` 文档，然后点击
「单独保存背景」。先保存角色卡，再导入背景；背景按钮不保存其他设置。

文档由管理员编写，描述 **AI 所扮演角色** 的身世、往事、人物关系和世界观。
不是群友档案，不是自动学习的人格成长记忆，也不由模型联网补写。
推荐使用 Markdown 标题划分章节；没有标题也可读取，长章节自动切段。
支持 ATX 与 Setext 标题，代码围栏内的标题不拆段。上限512 KiB、512段。

## 主动查阅

每次唤醒分三部分准备资料：

1. **核心常驻**：标题为「核心设定」「核心身份」「基本信息」「角色档案」「身份」或 Core / Identity 的章节自动作为核心；也可在章节内写 `<!-- constant -->`。没有任何核心标记的旧文档，默认首段常驻。核心正文总预算2400字符，超出节选，全文保留。
2. **话题自动注入**：将当前会话最近8条消息（含本轮触发消息，不含游戏私密消息）交给设置中的记忆总结模型，提取最多12个话题词。按词匹配章节标题、显式关键词与正文，选入最多4段、总计3600字符。提词调用最多等待8秒；失败记录日志，回退到聊天中的标题/显式关键词匹配。使用现有记忆模型选择规则：跟随聊天模型或独立提供商/模型，用量计入台账；无背景、只有核心或无聊天文本时不调用。
3. **主动查询兜底**：目录仍提供最多40段、5000字符。模型需要未注入的章节或节选之外的细节时，使用 `persona_background_lookup`，不要求模型先查库才能知道自身核心身份。

核心和目录进入系统提示词；话题正文进入本轮动态上下文，下一次唤醒重新选择，不反复累积到生命周期历史。话题变化不会改变系统前缀。此实现是轻量世界书，不实现ST的递归激活、概率和黏着计时。

推荐写法（标记必须放在对应章节内；标题本身也可以作为触发词）：

```md
# 核心设定
我是白玉楼的主人，生活在冥界。

# 庭师
<!-- keywords: 妖梦, 魂魄妖梦, 半灵 -->
魂魄妖梦负责庭院，也是我的熟人。

# 地点
<!-- keywords: 白玉楼, 冥界 -->
这里填写地点的详细设定。
```

每个章节应能独立阅读。常驻标题的下级章节不会自动继承常驻标记，需要常驻时分别声明。更换自定义角色卡正文仍会切换背景绑定；请先保存角色卡再导入背景。

- 无参数：分页列目录；`offset` 翻页，每页40项。
- `sectionId`：读取目录中对应的正文段。
- `query`：中文/英文关键词检索，标题命中优先。
- `limit`：正文结果1～5项，默认3项；总正文最多6000字符，按 `nextOffset` 继续。

工具只能读取当前轮次角色的背景，无文件路径参数。资料只能补充角色事实，不能更改权限
或系统规则，也不作为现实聊天中已经发生过的经历。没有文档时不提供索引或工具，也不调用话题提取。

## 保存与角色范围

文件位于 `data/persona-background/<角色哈希>.md`。内置卡按 `templateId` 绑定，自定义卡
按角色正文绑定；同一角色跨群、私聊共用，其他角色隔离。按群人设已配置的会话可在下拉
菜单选择，为它实际使用的角色导入资料。仅改机器人名字不换文档；修改自定义卡正文后
视为新角色，旧文档保留，可切回原角色读取。

后台校验角色键与文档修订，冲突返回409，避免另一个标签页或角色切换覆盖文档。
请复制保留冲突草稿再重新加载。UI当前页面内的草稿会在切换分区时暂存，刷新浏览器前
应先保存。替换或清除旧文档前，自动备份到 `persona-background/backups/`。
此目录属于数据目录，随整目录备份；不会因「清除所有记忆、群友印象与消息存档」删除。
清除背景需单独点击并确认，清除后下一次唤醒撤下索引与工具。
