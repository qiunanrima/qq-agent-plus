# 长期记忆与检索

默认使用[海马两层记忆](HIPPOCAMPUS.md)：今日/昨日的周期摘要跨会话注入，凌晨3点消化为长期卡片；长期正文按索引查询。`memory.hippocampusEnabled=false` 可回退旧路径。新库 `hippocampus.sqlite` 纳入全量清除与备份，不自动删除任何旧印象。

下面说明原有记忆资产（继续保留）：

- **人物印象**：按 QQ 全局保存，每条最多 300 字，带来源会话与观察时间；
- **会话交接**：按 chatKey 保存，记录当前话题、假设、证据、决定与下一步。

人物印象是“养鱼”的核心数据；检索入口是 `memory_query`。

## 检索

`memory_query` 新增 `query` 参数：

```json
{ "query": "上次说的那家面馆", "limit": 8 }
```

实现：

- SQLite FTS5（`data/memory/search.sqlite`）；
- 中文按单字 + 二元组切词，拉丁按词切词；
- FTS 候选再用覆盖率、FTS 排名、新鲜度重排；
- 用户和来源可见性在截取最多 240 条候选之前筛选，避免其它用户或不可见来源挤掉相关记忆；返回前仍会再次检查可见性；
- 支持 1 字、2 字、短句和混合中英文；
- 索引是派生数据，损坏不会影响 JSON 记忆正文；找不到索引时会退化为内存扫描。

索引是**词法检索**，不是向量语义检索：

- “面馆 / 新开的面馆 / 谁提过面馆”能命中；
- 换成完全没有共同词的近义表达（例如“餐厅” vs “面馆”）可能找不到；
- 需要真正的语义召回时，后续可接 embedding；当前版本没有默认开启，避免把记忆正文发给第三方。

## 可见性

检索结果在**读取侧**再按 `memory.visibility` 过滤：

- `perChat`：只返回来源含当前会话的印象；
- `hidePrivateInGroup`：群聊里不返回私聊来源；
- 来源会话字段不会交给模型，控制台人物记忆页仍可查看。

## 上下文预算

历史消息受 `store.pastStateMaxChars` 与当前上下文档位共同限制，优先保留最近的消息，正常按时间顺序展示。如果最新一条消息本身超过整个字符预算，会保留其消息 ID、说话人及可用正文，明确标注截断；更早的消息仍按完整消息裁剪。上下文档位为零时不带历史。

人物印象注入最多覆盖 20 人、每人最近 3 条，默认整个块不超过 6000 字符；省 Token 模式可以进一步收紧。预算先分给每个人的最新一条，再补第二、第三条。放不下的完整印象会跳过，继续尝试后面的短印象，不把事实截成半句，也不输出只有标题的空块。

预算裁剪只影响本轮发送给模型的内容，不删除历史或记忆；需要更多事实时可使用历史查询与 `memory_query`。会话交接仍按原来的会话隔离、共享开关和过期时间处理。

## 容量与保留期

默认值：

- 每人最多 **50 条**人物印象；
- 每条最多 **300 字**；
- 自动印象保留期 **0 天 = 不按时间过期**（升级老库不会清掉历史）；
- 控制台手写的 `manual` 条目永远不因上限/保留期被删。

管理员可以在「设置 → 记忆」改成：

- 每人 5–200 条；
- 保留 0–3650 天（0 = 不过期）。

超过条数上限时，优先保留 manual，再按最近观察时间淘汰自动条目。

## 实测容量

在本机用 100 人 × 每人 50 条（共 5,000 条）跑容量基准：

- 人物 JSON：约 1.3 MB；
- FTS 索引：约 4.5 MB；
- 首次检索（含建索引）：约 150 ms；
- 2,500 条时热检索：p50 约 11 ms、p95 约 15 ms。

所以百万级聊天记录不会进这个库；长期印象本身是“每人最多 50 条”的小数据。真正占空间的是消息库和媒体文件。

## 召回基准

`test/memory-search.test.mjs` 内置 14 条合成印象和 10 个查询，覆盖：

- 2 字关键词（面馆、周会、爬山、火锅）；
- 单字（猫）；
- 完整短句（汤有点咸、取快递）；
- 改述（那家新开的店、周末去哪儿、谁提过面馆）。

当前结果：**recall@3 = 10/10**。这不是通用语义评测，只证明词法/二元组检索对群聊里常见的“人 + 地点 + 事件”问法有效；完全换词的近义问法仍可能漏。

## 备份与恢复

`search.sqlite` 位于数据目录内，会随 `ops backup` 一起备份；它是派生索引，删除后下一次检索会自动重建。人物印象 JSON 才是权威数据。

## 一键清除所有记忆

控制台「人物记忆」页提供「清除所有记忆、群友印象与消息存档」。确认框列出全群聊、全私聊的删除范围，取消不会发送删除请求。此操作不提供给 QQ 聊天工具。

- 清除全部聊天原始存档（含消息内的图片等媒体引用）、人物印象与熟悉度、身份档案中的印象字段、会话交接、线程轮次与检查点，以及长期语义记忆的卡片、向量和来源回合；派生搜索索引同步清空。旧消息不再供上下文和存档检索读取，新收到的消息仍正常存档。
- 保留人物身份与好友审批台账、备注、角色卡、白名单、模型配置、外部发送安全台账以及已有备份；保留消息编号计数以避免旧引用撞上新消息。本操作不撤回 QQ 消息、不删除独立媒体缓存，也不承诺磁盘取证级擦除。
- 先暂停机器人；若存在在途聊天、人物评估或记忆提炼/整理，返回 409，本次不删数据。等任务完成后可再次明确点击。操作结束保持暂停，由管理员检查并手动恢复回复。
- 删除前先把各模块快照写到 `DATA_DIR/memory-reset-backups/<备份编号>/`，目录 0700、文件 0600；消息库 `messages.sqlite` 和长期语义库均使用 SQLite 一致性快照。旧版 `messages/group_*.json`、`private_*.json` 也先复制到备份中的 `legacy-messages/` 再清除。任一备份失败则不开始删除。备份不在模型读取范围内，也不会自动恢复。
- 跨模块清理并非一个数据库事务；中途失败会明确报告阶段和备份编号，可能已有部分清除，不自动重试。需要恢复时先停止服务，按备份里的 `manifest.json` 核对范围后由运维恢复，不能将快照 JSON 直接替换成 `config.json`。
- 从未启用的语义记忆不会因清空操作创建数据库；禁用但已有数据的语义库也会清空。
- [人格成长记忆](PERSONALITY_MEMORY.md) 中的自身偏好、共同经历和关系变化也包含在本次备份及清除范围；停用时已有数据同样清除，从未启用则不新建人格库。

管理接口：`POST /api/memory/reset-all`，要求控制台鉴权与 JSON `{ "confirm": true, "scope": "all", "includeArchive": true }`。旧版确认请求返回 409，要求刷新页面以确认扩大的删除范围。成功返回清除计数和备份编号，不返回记忆正文。

清除成功提示会显示实际删除的消息条数。仅返回旧版上下文计数、没有消息删除计数时，不应视为存档清除成功。更新时注意：控制台自动更新只跟随已发布 Release，推送 `main` 不会触发它；需要使用新克隆的源码运行 `deploy.sh`，不要复用此前下载的临时源码目录。可读取 `DATA_DIR/deployed-revision` 核对部署提交。浏览器存档缓存会在清除成功及清除事件后失效，迟到的旧分页响应被忽略。
