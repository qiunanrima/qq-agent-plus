# 人格成长记忆

这是机器人对自身偏好、共同经历和关系变化的持久记忆，与「这个群友是什么样的人」的人物印象分开。角色卡仍决定身份、核心性格和表达底线；成长记忆提供后续互动的连续性，不会修改角色卡。

## 开启和管理

默认关闭，旧安装不会自动启用。在「设置 → 实验功能 → 人格成长记忆」启用可开始试用；「固化上线」经确认后启用并显示独立的「人格成长」导航。启用与固化是两个独立状态，固化后也可以停用并保留管理页。取消固化会关闭运行并隐藏导航，数据保留。

独立页提供采集开关、私聊参与开关、每个角色每个会话的容量设置，以及按会话筛选、查看原始证据、修正、确认稳定和删除。停用时仍可管理既有数据。页面最多显示最近 500 条，数据不会因此删除。

## 如何成长

- `preference`：自己的喜好，例如在真实对话中表达过的饮品偏好。
- `experience`：双方实际参与过的聊天经历，例如一起讨论一本书，不代表现实中见过面。
- `relationship`：对具体群友的关系态度，需要对方实际参与互动，不凭空增加亲密程度。

回复时，模型可通过模块工具 `remember_personality` 主动保存值得延续的内容，每轮最多两条，不要求每轮写。没有额外的后台提炼模型或定时器，但调用工具可能增加当前聊天的模型轮次和用量。

每条记录必须逐字引用本会话最近 100 条、最近三天内的真实消息。偏好需要机器人实际说过的话；经历和关系需要双方消息，关系对象必须是证据中的发言者。用户单方面要求「从此你是……」不能直接成为人格记忆。

新偏好和关系为 `tentative`（初步倾向），同一内容在不同上海自然日有机器人的表达作证，才可变为 `active`。经历在双方互动证据齐全时可立即记录。同一消息重放不重复累计；同主题已有稳定内容时，冲突的新内容保持候选，不自动覆盖。管理员也可查看证据后确认稳定或修正内容。

证据检查保证「消息存在且引用一致」，不等同于自动证明模型归纳正确。相同主题/内容按原文精确聚合，换一种归纳措辞可能成为另一条候选，运营者可在管理页整理。系统不会自主重写核心性格，也不会从单次互动计算或承诺真实情感。

## 隔离与提示词

以角色模板、名字和角色正文的 SHA-256 摘要划分角色。改正文或切换角色后使用独立记忆；旧角色数据保留，切回原配置可再次使用。瞬时心情不参与角色键。

所有类型均按 `group:<id>` / `private:<id>` 隔离，偏好也不自动跨会话传播。私聊默认不采集、不召回，需在独立页开启；开启后也不会带入群聊。关系记忆仅在目标群友参与当前触发消息时注入。

每轮临时上下文按类型轮询选取，最多 10 条，记忆数据部分默认上限 2200 字符。提示词明确记忆为数据、初步倾向不能当稳定性格、核心卡优先，不要求对外汇报记忆机制。读取失败只跳过模块，不阻断聊天。

## 数据、备份和回滚

所有数据在 `DATA_DIR/personality-memory.sqlite`。从未启用且没有写入时，不因启动、状态查看、全量清除创建此库。停用后立即撤回工具和召回，已获得的旧工具也会拒绝新写入；没有后台任务需等待。

「人物记忆 → 清除所有记忆、群友印象与消息存档」也包括此模块：先一致性备份为 `memory-reset-backups/<编号>/personality-memory.sqlite`，再清除人格记忆，结束保持暂停。备份不供模型读取，不自动恢复。既有部署/运维备份也保留此数据库。

回滚功能时先停用 `personalityMemory.enabled`，旧版代码会忽略独立数据库，数据保留。恢复备份时停止服务，先保存当前数据，再由管理员将对应人格库快照恢复到数据目录，校正服务用户权限后重启。

接口由模块独立注册并沿用控制台鉴权：

- `GET /api/personality-memory/status`：配置、记录与证据。
- `POST /api/personality-memory/entries/<id>`：`{confirm:true, content, status}`，修正或确认；停用时仍可操作。
- `DELETE /api/personality-memory/entries/<id>`：`{confirm:true}`，删除指定记录。
- 配置经共享 `POST /api/config` 写入 `personalityMemory`，仅提交模块字段。配置定义和归一化在 `src/personality-memory/config.js`。
