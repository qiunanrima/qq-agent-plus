# 人格成长记忆

这是机器人对自身偏好、共同经历和关系变化的持久记忆，与「这个群友是什么样的人」的人物印象分开。角色卡仍决定身份、核心性格和表达底线；成长记忆提供后续互动的连续性，不会修改角色卡。

## 开启和管理

默认关闭，旧安装不会自动启用。在「设置 → 实验功能 → 人格成长记忆」启用可开始试用；「固化上线」经确认后启用并显示独立的「人格成长」导航。启用与固化是两个独立状态，固化后也可以停用并保留管理页。取消固化会关闭运行并隐藏导航，数据保留。

独立页提供采集开关、私聊参与开关、每个角色每个会话的容量设置，以及按会话筛选、查看原始证据、修正、确认稳定和删除。停用时仍可管理既有数据。页面最多显示最近 500 条，数据不会因此删除。

## 如何成长

- `preference`：自己的喜好，例如在真实对话中表达过的饮品偏好。
- `experience`：双方实际参与过的聊天经历，例如一起讨论一本书，不代表现实中见过面。
- `relationship`：对具体群友的关系态度，需要对方实际参与互动，不凭空增加亲密程度。

回复时，模型可通过模块工具 `remember_personality` 主动保存值得延续的内容，每轮最多两次采集尝试，不要求每轮写。每次必须由设置中的记忆总结模型独立核验（跟随聊天模型或使用独立提供商/模型），最多等待30秒。背景话题扫描与人格核验的用量保存在当前运行的 `auxiliaryUsage`，与聊天用量共同约束 `maxRunTokens`；请求前估算输入、预留回复额度并限制辅助输出最多2048 Token，余额不足则跳过辅助调用。每日台账仍按辅助调用的实际模型计价一次，不重复并入聊天模型账目。没有额外定时器。核验失败、结构非法或服务不可用时不写入，不自动接受主聊天模型的结论。

每条记录必须逐字引用本会话最近 100 条、最近三天内的真实消息。偏好需要机器人实际说过的话；经历和关系需要双方消息，关系对象必须是证据中的发言者。用户单方面要求「从此你是……」不能直接成为人格记忆。

新偏好和关系为 `tentative`（初步倾向），同义内容在不同记忆日（北京时间03:00换日）有机器人的表达作证，才可变为 `active`。经历在双方互动证据齐全时可立即记录。同一消息重放不重复累计。只有核验模型明确标记的语义冲突才阻止自动稳定，同一主题的独立事实可以共存。冲突关系持久保存；管理员确认其中一条稳定时，只降级与其有冲突关系的条目，不降级同主题的其他事实。管理员也可查看证据后修正内容。

先检查消息存在、作者、时间和逐字引用，再将完整证据消息、角色卡、拟保存结论和旧记忆交给独立总结模型，核验结论归属、语义支持与临时情绪/人设指令等情况。核验返回同义条目id与冲突id；只接受本角色、同类型、同关系对象的合法id。同义内容跨会话合并为同一条，保留所有来源会话、证据和支持日期；稳定偏好的冲突检查也覆盖整个角色。总结模型仍可能误判，不保证语义判断绝对正确，管理员可查看依据后纠正。系统不会自主重写核心性格，也不会从单次互动计算或承诺真实情感。

## 隔离与提示词

以角色模板、名字和角色正文的 SHA-256 摘要划分角色。改正文或切换角色后使用独立记忆；旧角色数据保留，切回原配置可再次使用。瞬时心情不参与角色键。

默认[海马模式](HIPPOCAMPUS.md)下，正文保留来源会话，但同一角色跨会话共享人格索引，使用 `personality_lookup` 才展开正文。既有 `memory.visibility` 仍可限制跨会话或隐藏私聊来源。私聊默认不采集，需在独立页开启；当前私聊不开启时也不提供人格索引/工具。

关闭海马模式后仍按角色合并与检查冲突，但改为直接注入可见记忆正文；关系记忆仅在目标群友参与当前触发消息时注入。人格记忆按所有来源逐一检查：任一来源不可见，整条记录都不进入索引、正文查询或核验模型的旧记忆列表，精确文本匹配也不会绕过隔离合并。因为主题、正文与稳定状态本身可能由隐藏证据生成，不能只删引用后继续使用。开启 hidePrivateInGroup 后，含私聊来源的合并记录不在群里召回；perChat 下，历史跨会话合并记录也整条隐藏，原始数据保留在管理页。之后的新采集按可见来源独立积累。

关闭海马时每轮临时上下文按类型轮询选取，最多10条、数据默认上限2200字符；海马模式仅展示最多30条索引，更多索引可分页查询。提示词明确记忆为数据、初步倾向不能当稳定性格、核心卡优先，不要求对外汇报记忆机制。读取失败只跳过模块，不阻断聊天。

## 升级与统一人格来源

人格成长的新写入只由本模块管理。海马凌晨消化仅生成群友印象与技能笔记，不再另行生成人格卡；已有海马人格卡保留在原库，可在「海马记忆」页查看，但不再进入模型索引或查询结果。

旧人格库自动兼容升级，新增核验标记、来源会话与冲突关系字段。旧记录正文、证据和数据库原始状态不删除；没有核验标记的旧 active 在运行时降为候选，不能直接当稳定人格。旧库没有语义冲突关系时不会仅凭同主题批量降级。管理员确认后可重新稳定；再次采集并核验同义记录时，只用新核验过的证据重新累计。关闭后仍可管理旧数据。

模型等待时不持数据库锁。同一角色的修改、删除或并发采集导致该角色版本变化，会拒绝迟到结果，要求重新核验；不同角色的写入互不影响。清空或停用导致的取消仍使所有相关在途核验失效，避免清空后重新写回。

## 数据、备份和回滚

所有数据在 `DATA_DIR/personality-memory.sqlite`。从未启用且没有写入时，不因启动、状态查看、全量清除创建此库。停用后立即撤回工具和召回，已获得的旧工具也会拒绝新写入；在控制台关闭采集、停用或重载停用配置会取消正在等待的核验；清空会使所有迟到结果失效。

「人物记忆 → 清除所有记忆、群友印象与消息存档」也包括此模块：先一致性备份为 `memory-reset-backups/<编号>/personality-memory.sqlite`，再清除人格记忆，结束保持暂停。备份不供模型读取，不自动恢复。既有部署/运维备份也保留此数据库。

回滚功能时先停用 `personalityMemory.enabled`，旧版代码会忽略独立数据库，数据保留。恢复备份时停止服务，先保存当前数据，再由管理员将对应人格库快照恢复到数据目录，校正服务用户权限后重启。

接口由模块独立注册并沿用控制台鉴权：

- `GET /api/personality-memory/status`：配置、记录与证据。
- `POST /api/personality-memory/entries/<id>`：`{confirm:true, content, status}`，修正或确认；停用时仍可操作。
- `DELETE /api/personality-memory/entries/<id>`：`{confirm:true}`，删除指定记录。
- 配置经共享 `POST /api/config` 写入 `personalityMemory`，仅提交模块字段。配置定义和归一化在 `src/personality-memory/config.js`。
