# 微信接入（Agent WeChat）

微信是协议接入层，和 QQ 共用 `Orchestrator`、会话运行记录、角色卡、模型、
CLI 全局队列及发送账本。CLI 启用时微信和 QQ 都使用 ACP；微信原生文件与命令权限
独立关闭，不会因为共用 ACP 自动继承 QQ 审批权限。没有第二套模型回复循环。默认关闭，支持私聊文字、图片和协议可下载的表情包。
协议服务单独运行，接入仅使用其本机认证 HTTP API；QQ OneBot 配置不变。

设置 → 实验功能 → 微信接入 → 打开微信接入。连接项填写 Agent WeChat 的
本机地址、账号 ID 和服务用户可读的私有令牌文件路径。令牌内容不进入模型或页面。
白名单每行一个 wxid，空名单拒绝全部；QQ 白名单和管理权限不会继承。
微信接入页可点「从微信联系人选择」，按昵称、备注、微信号或 wxid 搜索并勾选；
联系人来自当前配置账号的协议端已同步列表，可分页加载。确定选择后需保存微信设置才生效。
尚未同步资料的已选 wxid 会保留；读取失败和取消选择均不清空原白名单。
未绑定联系人按 wxid 独立处理。加入白名单不要求绑定 QQ。
微信群使用独立的 `groups` 白名单，格式为 `数字@chatroom`，默认空；可从微信页面选择群。
群成员身份按消息发送者记录，群会话不会继承某一成员的 QQ 身份或管理员权限。
`nativeApproval` 是微信独立开关，默认关闭；开启后文件/前台命令每次经 ACP 请求管理员审批。
微信正常结束的摘要可进入海马，保留 wxid 参与者；微信来源仅在原会话可见，绑定仍按原规则读取人物印象。

绑定填 `wxid QQ号`，只关联指定 QQ 的人物记忆（包含可见的海马人物卡片），不读取
其他 QQ 聊天存档。微信会话历史、交接总结和消息 ID 始终按协议账号与 wxid 隔离。
当前绑定用于读取已有的人物记忆；不把微信 wxid 冒充 QQ 号写回旧人物档案。
解绑不删除已存记忆。微信不提供 QQ 操作工具；原生文件与命令权限由微信独立审批开关控制。

文字发送、历史与消息详情、记忆查询、角色背景、联网、知识库、技能和额度等通用工具
沿用统一 Agent 的定义及配置开关。人物、海马和人格查询按当前 wxid/绑定 QQ 限定；
拍一拍、群管理、空间、QQ 媒体发送等协议专属能力不会混入微信。原生工具被拒绝时
由 ACP 返回拒绝结果，不能绕过审批；其后可继续使用本轮授权的 MCP 工具。

`get_message_images` 在微信回合中绑定微信账号和当前 wxid，只接受当前会话存档里的
消息 ID。媒体通过本机鉴权 API 下载，不把令牌、CDN 地址或任意文件路径交给模型，
不借用 QQ OneBot。下载有 12 MiB 上限，模型图像有 4 MiB 上限；GIF 沿用现有
ffmpeg 四帧拼图。ACP 只允许读取本轮工具生成、通过内容校验的图片，其他原生文件
和命令权限仍关闭。协议拒绝来源（例如 `sticker_source_not_allowed`）、下载失败、
撤回或身份不匹配时明确报告未看到，不自动改走外部 URL。只读工具失败后，模型应如实说明，
再以 `errorAcknowledged: true` 结束；不能把失败描述成已经看到了图片。

`list_stickers`、`get_sticker_image` 和 `send_sticker` 可使用已缓存的本地表情图片，
不触发 QQ 下载或发送。微信发送走鉴权 `/uploads` 和图片发送任务，按回执确认成功，
结果未知不自动重发。这是普通图片，不是微信原生表情；暂不支持引用、@、拍一拍、
语音或文件发送。上传及任务回执已通过离线契约测试，手机端图片实际显示仍需实测。

微信入站消息和 `get_active_members` 使用协议端联系人昵称、备注及群名片；优先群名片，
资料缺失才显示 wxid。查询有五秒总超时与缓存，失败不阻塞收消息。已存消息不回填昵称。
群内人物查询仅接受当前记录中出现的成员，默认只返回来源明确的群内印象。
微信接入页的「QQ 群及微信群可读取绑定成员另一平台的私聊来源记忆」默认关闭；
开启后 Agent 可查询绑定成员的私聊来源记忆，由 Agent 结合场合决定是否提及。

绑定后的双方都有 `cross_platform_memory_lookup`：QQ 可按绑定 wxid 查询微信私聊的
海马摘要与人物卡片，微信可反查绑定 QQ 的摘要、人物卡片和人物印象；可传 `userId`、
`query`、`offset`。仅返回同角色、明确绑定对应的记忆，不读取完整聊天记录，不修改
原记忆。群聊调用同样遵循上述开关，只接受本轮参与者的绑定。停用或解绑立即阻止查询。
两边的本轮上下文都会说明相关绑定和查询工具；微信成员列表附带绑定 QQ。
微信摘要尚未生成、已清除或角色不同会返回空结果，空结果不等于绑定失效。

全局 QQ 管理员在 **QQ 私聊** 中也可直接管理，不经过模型：

```text
微信白名单 添加 wxid_xxx
微信白名单 移除 wxid_xxx
绑定微信 wxid_xxx 123456789
解绑微信 wxid_xxx
微信绑定
微信白名单
```

绑定不自动加入白名单。绑定和白名单修改有审计记录，发送通知失败不重做变更。

首次开启先跳过协议服务已有事件，从新的实时私聊开始处理；不回扫旧聊天。
每个微信回合只允许当前会话的文字发送，最多四条、每条 2000 字。发送在现有
outbox 中预记账，协议端采用固定幂等键。`accepted` 表示服务器接受；超时、
断线或未知结果将阻塞当前微信会话，核对后再通过现有异常/会话入口处理，不自动重发。

停用仅撤销微信接入和微信在途回合，保留数据、绑定和协议端登录；不停止或关闭
QQ 的会话、CLI 池、队列或 OneBot。协议服务故障只在微信页面报告。
固化与启用独立，固化后微信设置入口显示在平台分区。

回滚：先停用微信接入，再撤回本次代码部署。QQ 原配置、记忆、消息存档均无需迁移。
不要删除 Agent WeChat 的登录目录或发送回执来尝试重新登录。

验证：`node --test test/agent-wechat.test.mjs` 和
`npx playwright test test/browser/agent-wechat.spec.mjs`。
离线用例覆盖真实统一 Agent 的微信/QQ 回合、消息去重、白名单、绑定、未知发送、
上下文隔离和停用时 QQ 请求继续运行；不会调用真实模型或发送微信消息。
