# B 站轻量版

独立插件 ID：`bilibili-lite`，版本 `1.0.3`。要求宿主 `0.9.17+`，使用其中的 B 站私信接入、免审批发送与管理员通知机制。
原版 `bilibili` 保持官方 v1.1.1，两个插件可同时安装，不互相升级、覆盖或共享凭据。

## 保留功能（10 个工具入口）

| 工具 | 功能 |
| --- | --- |
| `search` | 关键词搜索；`kind=popular/ranking/weekly` 查看热门、排行榜和每周必看 |
| `video` | 视频详情、热门评论、字幕语言；`withDanmaku=true` 读取弹幕 |
| `user` | UP 主资料、直播状态和最近投稿 |
| `account` | 登录自检、历史、收藏夹、关注、通知；`what=message_sessions` 查看私信会话，`what=message_history` 加 `mid` 阅读文字私信 |
| `messages` | 专门读取私信：`what=sessions` 列会话，`what=history` 加 `mid` 读正文 |
| `login` | 扫码登录、状态检查、退出 |
| `interact` | 点赞/取消、投币、收藏、关注/取关、一键三连 |
| `comment` | 发评论、回复评论、时间戳链接 |
| `dynamic_publish` | 发布纯文字动态 |
| `message_send` | 向指定 `mid` 发送文字私信 |

已删除发弹幕、视频下载合流及发送、字幕全文/语音转写/抽帧理解。插件不申请 `media` 权限，
也不访问视频流域名。仍有 `send` 权限，仅用于在管理员私聊中发送登录二维码文本。

## 安装与账号分离

在控制台手动安装 `bilibili-lite-1.0.3.tar.gz`，然后在「B 站轻量版」自己的设置中重新扫码登录，
或手动配置 Cookie。旧版 B 站插件的登录态不会自动复制。
新插件数据、凭据、批准和配额按 `bilibili-lite` 单独保存；卸载它不会卸载原版。
若同时启用两个插件，模型会看到两套相似工具，建议按需要停用其中一个。

## 写操作与私信

动态发布、私信发送、评论和互动分别设有写开关，默认关闭。动态和私信开启后免逐条审批，执行后自动私聊管理员，包含动态正文或私信收件 UID 与正文。
评论与互动仍需管理员批准，正文变化需要重新批准。动态每日 5 次、私信每日 20 次，插件写入间隔至少 60 秒。
动态正文保守上限 6000 UTF-8 字节、私信 2000 字节（包含检查用的 JSON 结构开销）。

只有管理员或已鉴权控制台可以读取私信；建议在管理员私聊中查询。
阅读不标记已读，隐藏撤回正文；发送会标记对应会话已读。
`nextCursor` 需原样作为 `cursor` 传回，UID 和游标使用字符串。

超时、非 JSON 响应或缺少发送凭据按结果未知处理，不自动重发，也不退回批准与配额。
接口接受不等于公开或送达，请先到 B 站核对。关闭对应开关或整个插件可停止功能，配置与账号数据保留。

实现参考社区的 [动态发布接口](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/dynamic/publish.md)
和 [私信接口](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/message/private_msg.md)。
自动化测试使用模拟 HTTP，尚未验证真实账号的风控与送达。

私信发送需要配置管理员 QQ（`admin.ownerUin`）。通知失败会在调用结果中返回失败原因并记日志，
不会把已发送的私信当成失败重发。结果未知时通知会明确提示核对，不会谎报成功。

## 自动收信与独立白名单

在「私信接收与白名单」设置组配置：

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 自动接收私信并交给 AI | 关闭 | 开启后按配置间隔检查，有新文字私信才唤醒 AI；检查本身不调用模型 |
| 私信检查间隔（分钟） | 1 | 用户可设置1–60分钟 |
| 启用收信 UID 白名单 | 开启 | 只接收/读取收信名单中的 UID；空名单拒绝全部 |
| 收信白名单 UID | 空 | B 站 UID，用空格或逗号分隔，最多100个 |
| 启用发信 UID 白名单 | 开启 | 只允许发给发信名单中的 UID；空名单拒绝全部 |
| 发信白名单 UID | 空 | 与收信名单互不影响 |

「需要批准的动作」区域中的私信发送开关独立控制发信（标签已说明免逐条审批）。
可以只开收信、关掉发送；也可以关闭自动收信，仍通过 QQ 会话中的工具发送给发信白名单。
关闭某方向的白名单开关表示不限制该方向 UID，不会自动打开该方向功能开关。
手动读取私信仍限管理员/控制台，并受收信白名单约束。

首次开启建立游标基线，不唤醒 AI 回复旧记录；之后最多回收每位用户最近50条中的新文字消息，
新鲜度窗口至少10分钟，检查间隔超过8分钟时扩大到「间隔+2分钟」。撤回、图片、系统通知、自身消息和白名单外内容不会唤醒 AI。
每轮最多处理10个有更新的会话、20条消息，后续轮次继续收取；账号分别保存游标。
新消息进入独立 B 站会话，不混入 QQ/微信共享私聊记录，也不授予 QQ 管理权限。
模型只获得当前会话的回复、结束及历史查询工具。

消息先落库去重，再由宿主确认游标；收取或确认失败可重试读取，不会重复入库唤醒。
回复仍走每日20条、60秒间隔、发信白名单、发送后管理员通知及持久化 outbox，未知发送不自动重试。
停用插件或自动收信即停止新的投递；保留游标、会话和配置。暂未接入 B 站实时推送，采用用户设置间隔的定时检查。
管理员通知是发送结果通知，不是每条新收信的额外通知。

手动查私信优先调用 `messages`，不要把 `account notifications` 的回复/@/点赞通知当作私信。
旧入口 `account message_sessions/message_history` 继续可用；无效参数会提示完整支持列表与正确私信入口。
