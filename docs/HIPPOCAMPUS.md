# 海马与跨会话记忆

这是核心记忆链路，不是实验开关。`memory.hippocampusEnabled` 默认 `true`，现有配置升级后补默认值。设为 `false` 可回到原来的印象自动注入与自动整理方式；海马数据库保留，不删除旧记忆。

## 两层记忆

- **海马**：当天与昨天具体发生的事情。每个会话独立划分互动周期，摘要跨群聊、私聊共享。同一角色在别处聊过的事，可以在当前会话接上。
- **长期记忆**：人物印象、人格经历与学过的方法。提示词只列索引，正文由模型需要时调用工具查询。已有角色卡继续提供核心人格，不由日记覆盖。

共享以同一角色卡为边界。角色正文、模板或机器人名字变更后会切换角色索引；旧数据保留。已有 `memory.visibility.mode=perChat`、`hidePrivateInGroup=true` 仍同时约束海马、卡片和人格查询。默认 global 允许跨会话读取；它不意味着可向群友公开其他私聊的原话。

合并后的长期卡片按所有来源逐一检查权限，不能仅因其中包含当前会话就放行整条正文。`perChat` 下混合多个会话的旧卡片整条隐藏；群聊隐藏私聊来源时，含私聊来源的卡片也整条隐藏。后台原始记录保留，可见性恢复后可再次查询。

不共享消息发送目标、运行租约和外部操作状态。海马中的其他会话经历标明其他群聊/其他私聊，避免误认为发生在当前群。

## 周期摘要

复用现有注意力/对话生命周期，不重写激活规则，不增加弱注意期的模型调用。成功处理的回合通过 `finish.episodeSummary` 生成最多100字的周期简记，内容是本周期的人事、事件、话题与有依据的感受。后续回合结合前情更新同一摘要，而非为每条消息新增日记。显式结束或三分钟无成功处理的新回合后，下一次互动新开周期。跨凌晨3点也另开周期。

旧模型不填写新字段时，退回到 finish/交接摘要；再缺失时只摘录真实消息。这种兜底不另付费调用总结模型，摘要质量依赖主模型。未唤醒模型的旁听消息不会单独产生海马；在下一次活跃时由已进入上下文的前情参与总结。

摘要落库与回合id去重在同一事务中，重启不丢失，也不会重复累计同一回合。聊天失败或工具中止不会当成成功经历写入；游戏秘密等非普通消息不采集。

## 凌晨3点

按北京时间03:00换“记忆日”，例如11月2日02:59仍属11月1日；03:00开始新的今日。

1. 消化刚结束的记忆日，提取以后仍有价值的人物印象与明确教会且确认记住的方法。人格成长统一由独立模块核验证据，不再通过摘要直接生成人格卡。百科事实、临时情绪和猜测不沉淀。人物卡每人一张，正文最多130字；其他卡最多500字。
2. 消化结果与摘要的 `digested` 标记在同一个 SQLite 事务中提交。
3. 刚结束的一天标为“昨日”，其具体摘要继续可读。更早且已经成功消化的摘要才删除；长期卡片保留。

正常运行时由现有5秒恢复循环触发检查，不另建定时器。每批最多80条摘要，大量积压分批处理；检查最少间隔一分钟。模型返回不合法、网络错误或写库失败时原摘要保留，最少一小时后再试。过旧但未消化的摘要留作补偿，不自动塞进提示词；服务恢复后继续处理。

暂停、观察模式、停止运行、`memory.consolidateEnabled=false` 或当日预算耗尽时，不做付费消化。恢复后补处理。清空、暂停或停用期间迟到的模型结果不能重新写回。

## 注入与查询

海马每轮自动注入，今日/昨日交替分配6000字符摘要预算。存储没有按条数截断；超出提示词预算的内容可分页查。

| 工具 | 用途 |
| --- | --- |
| `hippocampus_lookup` | 按今日/昨日、QQ、关键词分页查询事件摘要，每页20条 |
| `memory_query(userId)` | 查询某人的长期印象，包括旧印象与新消化的人物卡 |
| `memory_query(query)` | 检索旧印象与新人物卡，结果不含来源会话标识 |
| `memory_card_list` | 按类型、人物分页查看长期卡片索引，每页30条 |
| `memory_card_lookup(id)` | 展开人物、技能卡正文 |
| `personality_lookup` | 已启用人格成长实验时，跨会话查询同角色人格索引/正文 |
| `skill_list` / `skill_use` | 原有安装技能索引/流程，仍受技能开关及会话授权约束 |
| `semantic_memory_lookup` | 已启用旧语义记忆时按需查询，代替自动展开 |

刚进入活跃时提示词列出在场QQ及可用旧印象索引，引导先查询再接话，不自动展开印象。人格成长实验关闭时不提供其工具；旧海马人格卡保留供管理员查看，但不会通过 `memory_card_lookup` 或索引向模型提供。

新模式不提供日常 `memory_append`，长期印象由凌晨消化生成；控制台手工旧印象仍保留。已有角色卡、技能注册表和旧记忆不清空、不迁移成附件里另一个项目的数据。方法卡是非执行性笔记，不自动安装插件、写代码或获得工具权限；实际执行仍遵守现有技能与工具机制。

## 存储、运维、回退

生命周期续接只携带最新一份海马、印象/人格/技能索引及交接快照。
快照在本轮模型调用中可见，但不重复写入生命周期历史；真实聊天和已查询的工具结果仍保留。
快照按准确添加的前缀长度剥离，不扫描或删除群友正文中的同名标题。
提示词改动使旧生命周期前缀失效，下次唤醒重新建立线程，不继续带旧版累积快照。

新增 `DATA_DIR/hippocampus.sqlite`，包含 `episodes`（周期摘要）、`turns`（回合去重）、`cards`（长期卡片）。首次有效采集时才建库；读取、启动、从未启用时的清空都不会建空库。文件0600，目录0700，模型等待期间不持有数据库锁。

控制台鉴权后可读 `GET /api/memory/hippocampus?offset=0`，查看当前记忆日、是否正在消化、待消化数量、摘要和长期卡片，每页40条。控制台侧栏「海马记忆」提供独立只读页面，展示今日/昨日与更早积压摘要、消化状态、来源会话和长期卡片，支持刷新、分页与失败重试。历史人格卡标为仅供管理查看，不参与回复。

“清除所有记忆、群友印象与消息存档”包含海马与长期卡片：先生成一致性SQLite备份，再清除。消化进行中会先暂停并提示稍后再清，不会与删除并发。备份在原有 `memory-reset-backups/<id>/hippocampus.sqlite` 中，不进入模型读取范围。运维备份及数据库审计也涵盖该库。

回退时将 `memory.hippocampusEnabled` 设为 `false` 并重启：恢复旧自动注入/整理路径，新库仍在。停服务后可从一致性备份恢复该文件。不要仅复制运行中的数据库，也不要把备份放进模型可查询的目录。

实现没有照搬附件中的人格七维数值漂移、技能置信度奖惩、特定机器人姓名或全新三态调度器；本次范围是两层记忆、按日消化、索引查询与跨会话互通。
