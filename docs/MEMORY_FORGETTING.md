# 有限上下文与记忆遗忘

海马的今日/昨日摘要、凌晨3点换日和消化流程保持原样，不参与遗忘。
长期人物印象、技能卡、人格成长记录仍由各自模块保存。遗忘只影响自动展示和召回排序，
不按保留率删除正文；原有显式删除、旧人物库容量/保留期设置仍按其独立规则执行。

## 最近聊天与历史查询

设置 → 聊天 → 限制自动携带的最近聊天，可设置20～100条，默认50条；
字符预算默认8000，同时受响应档位及省Token设置限制。旧安装明确关闭分层上下文时
保留该选择，需要在此开启。限制的是自动携带的已处理历史，待处理触发消息仍按批次预算消费，
不会为凑50条跳过未处理消息。生命周期续接继续受既有线程/Token预算控制。

`search_history` 在当前会话的 messages.sqlite 中按关键词、人物、时间查询，
每次最多20条，每条600字符；时间需使用带时区的ISO格式。仅查询已处理的普通消息，
排除游戏秘密，继续应用屏蔽名单。关键词按字面子串匹配，不作为SQL语句执行。
更早记录保留在档案中；查询未命中不证明没有发生过。需要正文可用 get_message_detail，
需要翻页可用 get_recent_messages。

简单问题由主模型直接查询；跨时段调查可使用已启用的 delegate_research。
子代理沿用每轮2次、3轮模型、4次工具的硬限制，只获得只读档案接口。
子代理最终采用的长期记忆应在结论中保留 recallId，供主模型确认使用，
它读取的其余结果不会被批量强化。子代理未开启时不额外调用模型。

## 遗忘与强化

设置 → 记忆 → 长期记忆自然遗忘与使用强化，控制 memory.forgettingEnabled。

```
t = 距最近一次有效强化或真实观察的天数（不小于0）
S = min(90, 1.84 × (1 + ln(1 + recallCount)))
R = exp(-t / S)
```

新记忆S为1.84天。R低于5%退出自动索引/旧模式自动正文，主动查询和索引分页仍可找到。
明确关键词查询保留冷结果资格，以相关度为主、保留率作轻量排序因素。
保留率不是可信度，不会把反复提及的内容自动判为事实。

读取正文返回 recallId、recallCount、strength、retention、lastReinforcedAt。
展示索引或搜索命中不写入调取次数。模型在成功finish的 usedMemoryIds 中声明本轮实际采用的ID，
宿主仅接受本轮已读取正文的ID；每条记忆每24小时最多强化一次，重放不能重复计数。
未调用finish、查询失败、收尾失败、取消和未采用均不强化。模型声明是使用信号，
宿主不能独立证明某句话确实在语义上采用了该记忆。

强化元数据保存在 memory-recall.sqlite，不复制记忆正文。按角色/类型/人物/正文形成键，
正文变更不会继承旧结论的强化。读取和从未启用的功能不会创建该库。
停用保留元数据、不写入，恢复后按实际经过的时间继续衰减。
全量记忆清除会先备份该库再清空；该库只记录使用强度，不能用于恢复记忆正文。

## 回退

关闭遗忘开关即可恢复不受衰减过滤的索引/旧模式正文；关闭聊天窗口限制即可恢复旧档位上限。
两者都不删除数据。无需回滚数据库结构；memory-recall.sqlite 是独立的使用元数据库。
