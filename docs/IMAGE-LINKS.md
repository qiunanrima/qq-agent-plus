# 聊天中的图片链接

用户发送的裸 HTTP(S) 链接或 Markdown 链接，会在消息接入时尝试识别为图片，包括没有扩展名的 QQ 图床链接。识别成功后保留原文，附加 `[链接图片]` 标记，并把图片加入消息媒体。模型通过原来的 `get_message_images` 识图，GIF 仍走原来的抽帧转换流程。

识别按图片字节魔数判断，当前支持 PNG、JPEG、GIF、WebP。普通网页在响应头处跳过；无 Content-Type 或返回 `application/octet-stream` 的内容也会检查魔数，伪装成图片的 HTML 不会被送去识图。只检查用户实际发送的文本，不从网页、引用预览或卡片摘要中继续提取图片。

缓存位于数据目录的 `cache/image-links/`，文件名是链接的 SHA-256，消息媒体只保存原链接与缓存标识，不把图片 base64 塞入消息库。识图和自动表情判断优先读缓存；原链接失效也不影响有效缓存的使用。缓存失效后，识图工具仍可尝试原来的下载路径。

边界：

- 每条消息最多探测 4 个不同链接，单张不超过 12 MiB，整次探测最多 8 秒。
- 缓存有效期 10 分钟（从下载成功起算，读取不续期）；新写入时清理过期与最旧文件，最多保留 256 个文件、128 MiB。
- 下载沿用安全抓取的 DNS/IP 校验、重定向复查及响应大小限制；自动探测始终禁止内网，即使管理员打开了手动图片的内网例外。
- 关闭「消息类型 → 图片查看」后不再自动探测。白名单外、屏蔽用户和命中关键词黑名单的消息不探测。探测失败保留原消息，不自动重试。
- 自己发的消息不自动探测，已是原生图片媒体的同一链接不重复下载。
