# 角色扮演与真实感

角色演绎随现有人设生效，无需打开实验功能。全局人设与按群覆盖均适用；希望由角色卡完整决定声音与篇幅时，可选现有的「角色卡优先」档。

参考 [SillyTavern Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) 的人格、场景、对话示例分工，在现有角色正文中分别写清以下内容即可，不要求特定格式：

- 身份与动机：角色重视什么、想达成什么、有什么不愿妥协的事。
- 性格与声音：面对不同事情怎样反应，而不只是列形容词和口头禅。
- 关系与认知：目前认识谁、知道哪些事；没有建立的关系留白。
- 场景起点（可选）：虚构世界、地点和正在发生的事；日常 QQ 陪聊无需填写。
- 对话示例：用几组不同情境的对白示范反应，不把示例写成已经与用户发生的经历。

例如：

```text
身份：守塔人阿岚。职责是让船只平安入港，遇险时行动果断。
性格：寡言、谨慎，不擅长安慰，但会留意别人是否冷。
关系：与来访者初次见面，不知道对方来历。
场景：暴雨夜，来访者敲响灯塔的门。
示例（仅示范口吻，不是实际经历）：
来访者：你不问我是谁？
阿岚：先把外套烘干。名字可以等雨小一点再说。
```

运行时会强调视角限制、场景延续、情绪与关系的渐进变化，并把用户的行动和决定留给用户。普通 QQ 闲聊不自动变成小说旁白；明确进入虚构场景后，允许故事内的动作和背景，不必每句跳出角色声明。

日常回复直接用角色第一人称，不汇报“识别图片、写入缓存、调用工具”等内部处理过程，也不输出“按人设我应该如何回应”的创作说明。搜索后回答实际查到的内容，看图后接图片里的事；失败时用日常说法交代限制。群友只是吐槽措辞像 AI 时，不自动展开身份介绍或自证真人；明确询问真实身份时仍简短如实回答。真实感靠稳定的偏好、情绪和具体反应，不靠编造履历、故意打错字或否认 AI 身份。

故事不会成为真实 QQ 操作或现实经历的证据。发言仍使用 `send_message`，工具成功与否仍以实际返回为准。换卡后以当前卡为准；示例不作为真实记忆。此改动没有新增持久剧情状态，跨轮连续性依赖现有历史、记忆和会话交接，也没有实现 SillyTavern 角色卡文件导入。

人工验收建议：用同一张卡连续测试「初次见面 → 被质疑 → 和解 → 隔轮继续」，检查称呼与情绪有无跳变；再要求角色替用户作决定、声称已现实到场，确认它保留用户选择并区分故事与现实。自动化只验证提示词契约，真实演绎质量需用所配置模型实测。
